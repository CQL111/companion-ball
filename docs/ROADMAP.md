# 产品路线图

> 这份文档描述**产品往哪去、为什么这么走、每阶段的验收标准**。
> 技术实现见 [`ARCHITECTURE.md`](ARCHITECTURE.md)；剥离历史见 [`STRIP-LOG.md`](STRIP-LOG.md)；
> 工程速查见 [`../AGENTS.md`](../AGENTS.md)。

## 一、定位

**它不是你的助手，是住你桌面上的一个小家伙。**

陪伴型角色的价值不在功能清单，而在于「你没看着它的时候它也活着」。
工具型桌面 AI 拼不过通用助手；养成型桌宠拼不过内容产能。我们能赢的地方是**性格、记忆、细节**。

### 三根支柱 + 一个容器

1. **在场感** —— 不点它，它也在动：呼吸、眨眼、打盹、伸懒腰、睡觉。
2. **记忆** —— 它记得你说过的话。这是「宠物」和「玩具」的分水岭。
3. **仪式** —— 每天有一个理由见它。不是每日运势（那是 fortune-ball 的领域）。
4. **猫的笔记本**（一等公民，不是「日记功能」）—— 同时是**记忆的界面**、
   **仪式的入口**、**许愿瓶的归宿**。详见第五节。

没有笔记本，记忆只活在聊天上下文里，用户永远不知道它记住了什么——
记忆功能等于没做。台词库决定它**会不会**说话，笔记本决定它**是什么人**。

### 刻意不做（非目标）

| 不做 | 原因 |
|---|---|
| 助手功能（天气查询、写代码、日程管理） | 通用桌面对话产品已经赢下这个市场，进入即无护城河 |
| 运势 / 黄历 / 签文 / 抽卡 | 与陪伴定位冲突，且属于 fortune-ball（见 `CLAUDE.md` 硬约束） |
| 传统交友（匹配 → 加好友 → 私聊） | 陌生人私聊必然引入骚扰与诈骗；产品矛盾见第四节 |
| 云账号 / 社交主页 / 关注链 | 陪伴是私密的；账号是一切社交压力的起点 |
| 把用户数据上传做「全局数据飞轮」 | 你唯一能打的牌是隐私；不做模型训练，上传改进不了任何东西 |
| 读取窗口标题 | 隐私红线。感知只用 `powerMonitor` 的空闲 / 锁屏状态 |

### 两条设计红线

- **打扰预算**：默认安静；主动开口每天 ≤2 次且深夜不主动；气泡不抢焦点、3 秒自灭；
  设置里提供「话多 / 话少」调节。桌宠第一大流失原因是烦，不是少。
- **微交互不走 LLM**：点击必须在 100ms 内有反应，走本地状态机 + 台词库。
  AI 只负责浮窗里的深聊。用户要的是「它活着」，不是「它在思考」。

| S6.2 | 1.1 | 定时投递 / 长字数 | 1–2 周 | 不影响曝光；不满即时可退 |
| S7 | 1.x | 成长与商业化 | 持续 | 关系等级；角色包 + 年度笔记本 + 信纸包 |

> **2026-11-20 路线调整**：许愿瓶原计划「单机 + AI 代答」用于验证需求，现按产品决定改为
> **真实用户互投**，因此 S3 直接引入服务端；原 S5/S6（猫邮局）的公开化与审核升级顺延为
> 后续阶段。这不是功能增加，是**产品性质变化**：从单机应用变成需要运营的用户内容服务。
> 风险与边界见 [`SERVER.md`](SERVER.md)。

顺序不可调换：**社交不能早于 S3**——没有角色黏性，用户不会为一封陌生人的信打开一只猫。
**社交公开上线可以延后**：先做许愿瓶（S3），再走邀请制 / 个人版的猫邮局（S5–S6），
公开版是否跟进看举报率与留存数据再定。

**手机端不在本表**——它是一次独立的产品决策（渠道、审核、支付、推送都不同），
但**每一阶段都要为它预留**：分层与跨端规则见第六节。

## 三、分阶段说明

### S2.6 · 皮肤与动作架构（0.6.0）✅ 已完成

> 在继续做剧情功能前，先把「角色怎么画」这条基础定下来，
> 否则每加一个动作都要手写一遍 SVG 姿态，换皮肤等于重做。

- **动作契约**（`src/core/motion.ts`）：14 个动作 × 两个视角，声明式清单，支持回退链
- **两视角**：`front`（待机 / 睡 / 舔爪 / 伸懒腰 / 被点 / 生气 / 眩晕 / 唤醒）
  与 `side`（走 / 爬 / 倒挂 / 腾空 / 落地 / 被拿起）。**只有侧影可镜像，正面永不翻转**
- **引擎预留**：`SkinManifest.engine` 支持 `atlas`（现在）与 `spine`（未来）；
  同一份契约下两个适配器，换皮肤只换素材，不改代码
- 渲染层用 Canvas 2D。现在不引入 PixiJS：同屏只有 1 个角色，性能不是瓶颈；
  等需要特效或 Spine 时只替换 `renderer.ts` 一个文件

**验收**：111 单测（含 motion 18 条）、16 项 e2e、真机逐动作截图验收。

### S2.5 · 它会在桌面上生活（0.5.0）✅ 已完成

> 补的是「身体」：S1/S2 给了情绪与记忆，但角色还钉在桌角。参考 Shimeji 类桌宠的玩法，
> 但**只爬屏幕四边**（不读取任何窗口信息），保持安静型节奏。

- 自主走动：60–180 秒一次决定，大部分时间待机；睡觉 / 打盹 / 菜单打开时不动
- 攀爬：走到左/右墙 → 沿墙上行 → 抵达屏幕顶部后倒挂行走 6–14 秒 → 落回地面
- 抛掷物理：松手速度决定轨迹，撞左右墙反弹（能量衰减），撞天花板，落地蹲一下
- 朝向翻转；行走 / 攀爬 / 倒挂 / 落地各有姿态动画
- 轻合成音效（WebAudio，无音频文件）：落地、被摸头、爬顶，设置里可关
- 领域层 `core/locomotion.ts` 纯函数，可单测、手机端可复用

**验收**：12 条物理/行为单测；real-app 观测 130 秒内出现 walk / land；e2e 15 项通过。

### S1 · 它有自己的生活（0.3.0）✅ 已完成

纯本地逻辑，不碰 AI。投入产出比最高的一步。

**状态机**：`醒着 / 好奇 / 打盹 / 睡觉 / 不耐烦`，由「当前时间 + 空闲时长 + 交互事件」驱动。

| 输入 | 行为 |
|---|---|
| 00:00–06:00 | 半睡（闭眼、呼吸变慢）；**不主动出声** |
| 06:00–10:00 | 首个交互 → 伸懒腰 + 早安 |
| 30 分钟无交互 | 趴下打盹；60 分钟 → 睡着 |
| 鼠标靠近（`pointerenter`） | 睁眼、抬头；离开后 2s 回原状态 |
| 连点 ≥5 次 / 10 秒 | 甩尾巴、背过去（不耐烦台词） |
| 拖起后快速甩放 | 眩晕动画 + 台词 |

**台词库**：80–150 条，按「状态 × 时段 × 触发」索引，冷启动读本地 JSON。
台词不是功能，是性格——宁少勿滥，禁止长句。

**交付**
- `src/core/petState.ts`（状态机，纯函数，**零平台依赖**）
- `src/core/quips.ts`（选台词：无重复抽样 + 冷却）
- `src/data/quips.json`（台词库，内容资产）
- 平台接入：`src/renderer/pet/pet.ts` 把指针/拖拽事件翻译成状态机事件；`store.pet` 持久化
- 设置页「给它起个名字」（≤16 字）
- 首次引导：起名（≤3 步），名字进 store
- 气泡层：不抢焦点、3s 自灭、`pointer-events:none`
- **清理 fortune-ball 残留**：S0 收尾时已完成（见 `STRIP-LOG.md` 的「残留清理记录」）；
  S1 只需接上情绪状态机，不再做删除工作

**可选延伸：猫的笔记本 v0**（不阻塞 S1 验收）
本地模板日记，零 token：用状态机 + 交互记录拼装，如「今天你把我挪到左边三次」。
只验证一件事——**打开率**（周活用户一周看 ≥2 次的人 ≥40%）。
没人看，就别在 S2 花钱让 LLM 写。

**改动面**：`renderer/pet/pet.ts`、`core/petState.ts`、`core/quips.ts`、`data/quips.json`、
`main/ipc.ts`（`set-pet-name` + `config-changed` 广播）、`shared/*`、`store.pet = { name, lastInteractAt, lastGreetDate }`。

**动画约束**：只能动 `.ball-inner` / SVG 分组，绝不能碰 `.ball` 的 transform（`AGENTS.md` 硬约束）。
**跨端约束**：状态机只输出抽象动作 `{ mood, action, intensity }`，不输出动画，
不接 Electron 事件——事件由平台适配器翻译后喂进来（第六节）。

**验收**
- 点击到首个像素变化 <100ms（已实现：同步切换 `data-mood` + 气泡，无网络往返）
- 7 日留存 ≥25%
- **开机自启被关闭的比例 <30%**——整个产品最重要的反向指标，超过说明它是麻烦不是陪伴
- 一周内主动交互 ≥3 次的人 ≥40%
- `npm test`（Vitest）覆盖状态机；`npm run check:core` 通过

### S2 · 它记得你 / 笔记本上桌（0.4.0）✅ 已完成

- **人格卡**：名字、物种习性（猫的傲娇、午睡、打哈欠）、口头禅、边界
  （「我是陪你的猫，不是心理咨询师」）。替换 `src/core/agent.ts` 现有的语气型 `SYSTEM_PROMPT`。
- **长期记忆**：对话结束后**异步**抽取 3–5 条事实（称呼、城市、近况、偏好），本地存储，
  上限 30 条，按时间淘汰。设置面板可查看、逐条删除、一键关闭。
  不进 prompt 原文，只进「事实摘要」。
- **猫的笔记本正式上桌**：
  - 日记由「**记忆摘要 + 模板**」拼装，**不是**每天雷打不动调 LLM；
    只在真有值得写的事时调一次便宜模型
  - 猫的第一人称，2–4 句，有日期，**允许空白**
  - 日记是长期记忆的**可视化界面**；设置里的记忆列表与笔记本共用一份数据
  - 支持一键导出 Markdown（本地，不同步、不分享）
- **主动互动分级**：久坐提醒 > 日程关心 > 纯闲聊，每日配额，随时可静音。
- 短期历史从 `HISTORY_TURNS = 8` 保持不变；长期记忆作为 system 附加块注入。

**交付（跨端）**
- `src/core/memory.ts`（抽取 / 裁剪 / 淘汰）、`src/core/notebook.ts`（日记拼装）
- 领域数据带 `id` + `createdAt`（UTC ISO），全部可 JSON 序列化
- **全量数据导出 / 导入**（不只是 Markdown）——手机端同步的唯一前提，见第六节

**验收**：重启后它仍能叫出用户称呼；对话中不出现记忆泄露（跨话题张冠李戴）；
主动开口次数可统计且默认 ≤2 次/天；日记打开率相比 S1 v0 不下降；
core 模块可在纯 node 下单测。

### S3 · 许愿瓶（联网 MVP，0.7.0）⏳ 进行中

> **进度（2026-11-20）**：客户端与 `server/` 全部完成并通过测试；本地 mock 跑通全流程。
> 尚未完成的只有**部署**（需 Cloudflare 账户）与**填默认地址**。
> 部署前客户端显示「猫邮局还没开门」，不产生网络请求。
> 因此本版（0.7.0）发布的是「就绪」，不是「完成」——验收标准「真实用户互投」要等部署后另发一版。

**真实用户互投**：你写一张纸条，它漂给另一个也在半夜醒着的人；对方可能回一句，也可能什么都不做。

- 扔瓶：≤60 字纸条，猫「出门」
- 收取：猫出门回来时可能叼回一张**真人**写的纸条（也可能是空手而归）
- 回信：可「悄悄回一句」，原投递者**永远不知道是谁回的、也无法追问**
- 瓶子夹进**猫的笔记本**——不另建「瓶子列表」，统一容器（见第五节）
- **不可私聊、不显示任何数字**（无已读、无点赞、无被捡次数）

**与旧计划的区别**：不再用 AI 代答验证需求，直接上真实用户。代价是引入服务端、
内容审核责任与运营成本——详见 [`SERVER.md`](SERVER.md)。

**交付**
- `src/core/mailbox.ts`（领域层，零平台依赖）：随机代号、时段同频、7 天沉海、
  投递/回信状态机、文本校验。桌面端只做「猫出门」的动画与定时，规则不落壳里
- `server/`（Cloudflare Workers + D1）：扔 / 捡 / 回 / 举报 四个接口 + 限流 + 紧急开关
- 客户端：设置里的「许愿瓶」开关（默认关，opt-in）、隐私政策增补、`AGREEMENT_VERSION` +1

**验收**：接口限流生效（单设备每日投递上限）；举报后内容立即对所有人不可见；
「有人写 / 有人回」两个比率可统计；`mailbox.ts` 用假时钟跑完整生命周期测试。

### S4 · 它看见你（0.8.0）

- `powerMonitor` 空闲 / 锁屏：锁屏时睡，回来时伸懒腰
- 久坐计时 → 提醒（唯一「有用」的陪伴功能，且不破坏角色）
- 天气（轻量 API）→ 雨天趴窗边、晴天晒肚皮（纯氛围，不播报）

**日记接入环境**：雨天、深夜、缺席都成为素材。
「你今天没来，我在桌上等到五点」——缺席是最有力的表达，而且不制造愧疚。

**验收**：空闲检测在 Windows 睡眠 / 锁屏下正确；除天气外不产生任何外部请求。

### S5 · 猫邮局（只读，0.6.0）

UI 不变，内容源换成真人内容池。**先只捡不扔**，用来验证审核管道。**全免费。**

- 后端最小实现：Cloudflare Workers + KV（日活千人内基本免额）
- 匿名身份：由现有 `installId` 派生令牌，**不做账号、不收集手机号 / 邮箱**
- 内容池：官方种子内容 + 邀请制小圈子；真没人时由猫兜底并标注
- 审核：入库机审 + 举报下架；举报率进入观测指标
- 「静默期」：只读阶段不允许任何用户内容进入池子的公开侧

**验收**：举报率可观测且 <0.5%；误杀 / 漏杀有日志可复盘；无一条内容带可识别身份。

### S6 · 猫邮局开门（1.0.0）

- 双向流转（扔 + 捡），**默认关闭，需主动 opt-in**
- `AGREEMENT_VERSION` +1，新增《猫邮局使用规范》，隐私政策明确
  「瓶子内容会离开你的电脑，但不绑定任何身份」
- 内容安全：正则拦截手机号 / 微信 / QQ / 链接，无图片
- **结构上不可私聊**：没有好友、没有会话、回信不保证送达（7 天沉海）
- **连接全免费**，上线后先跑 4 周再谈任何付费

**前置阻塞项**：收款主体资质（见第七节）。没有它，价格设计得再好也收不了一分钱。

**验收**：日举报 <0.5%；0 例成功导流；回信送达率作为产品指标而非 SLA；
4 周后用户是否**自然提出**「能不能写好一点」——没有需求就不进 S6.1。

### S6.1 · 信纸信封（装饰付费，1.0.x）

只上**纯装饰、0 功能差异**的信纸 / 火漆 / 邮票。观察转化与投诉。

**验收**：转化可观测；0 投诉；不出现「付费更容易被捡到」的暗示。

### S6.2 · 定时投递 / 长字数（1.1）

有功能差异但**不影响曝光**：定时投递（如只在 23:00 寄出进深夜同频池）、60 字 → 200 字。

**验收**：免费与付费瓶子的 7 天沉海规则完全相同；不满可即时退款。

### S7 · 成长与商业化（1.x）

- 关系等级：陌生 → 熟络 → 黏人，解锁动作 / 台词 / 皮肤
- 收入结构（按优先级）：**角色包 / 皮肤** > **年度笔记本** > 信纸包
- **不做抽卡、不做订阅自动续费、不把陪伴核心功能锁进付费墙**
- **连接永久免费**（被捡到、被回信不收费；装饰与投递方式可选付费，见第七节）

## 四、猫邮局：为什么不是「交友」

传统交友的本质是**建立关系**：匹配 → 加好友 → 私聊 → 维护。
这条路对桌宠是毒药——私聊一旦存在，骚扰、诈骗、导流全部进来。

我们要的是**孤独的确认，不是关系的建立**：一次性的、无回声的、不可追问的连接。
用户是「孤独但不想社交」的人，他们要的是「世界上还有别人也这样」，不是新朋友。

| | 传统漂流瓶 | 交友 App | 猫邮局 |
|---|---|---|---|
| 连接 | 捡到 → 加好友 | 匹配 → 私聊 | 捡到 → 看一眼 → 回一句 → **断** |
| 身份 | 头像昵称 | 全套人设 | 每次随机代号，不复用 |
| 关系 | 可延续 | 必须延续 | **结构上无法延续** |
| 频率 | 无限 | 无限 | 有配额 |
| 数字 | 已读 / 点赞 | 全套 | **一个都不显示** |

几个决定体验的细节：

- **不做固定匹配，只漂同频**：深夜扔的瓶子只漂给另一个深夜醒着的人。
- **没有数字**：没有已读、被捡次数、点赞。没有数字就没有社交比较。
- **回信不保证送达**：瓶子 7 天没人捡就沉海；你的回信对方可能早已漂走。
  错过的感觉很真实，而且天然阻断对话。
- **载体是角色不是功能**：不是「你去捡瓶子」，是「猫会出门，叼东西回来」。
  随机出门，不由用户按按钮触发。

## 五、猫的笔记本：产品的一等公民

不是「日记功能」，而是**一个容器**：

| 角色 | 说明 |
|---|---|
| 记忆的界面 | 长期记忆不能只活在 prompt 里；日记是它唯一可见的产物 |
| 仪式的入口 | 「打开猫的笔记本」比「和 AI 聊天」自然，没有聊天焦虑（不用你说话） |
| 瓶子的归宿 | S3 捡到的纸条、S5 的真瓶子，都夹进同一本 |
| 人格的载体 | 台词是骨架，日记是血肉；这是唯一能持续积累的性格资产 |

### 写作规则

- **猫的第一人称**，2–4 句，有日期，**允许空白**——真日记不会天天有话说
- **不出现任何数字和统计**

  > ❌「今日陪伴你 3 小时 20 分钟，共对话 12 轮。」
  >
  > ✅「你今天没怎么说话。我趴在窗口看了会儿雨，等你叫我。」

- 对所有素材都过猫的眼睛：**说感受，不说数据**
- 每天最多一条，有素材才写，宁可跳

### 边界

- **不同步、不分享**——那会直接推翻第四节「无回声」的设计
- **一键导出 Markdown**：用户会心疼丢，导出是最便宜的信任建设
- 关闭日记 = 关闭记忆的可视化，但记忆抽取本身可独立开关

## 六、分层与跨端预留（手机端）

### 结论先行

手机端不是「第二个壳」，它是一次独立的产品决策；但**领域逻辑与数据必须是同一份**。
所以从 S1 开始只守一件事：**core 层零平台依赖**。这一条今天做，成本几乎为零；
等手机端开工再补，就是重写。

### 现状：已经做对了一半

`src/core/agent.ts` 不依赖 Electron，`callLLM` 由调用方注入，Vitest 能在纯 node 下跑——
这就是正确的缝。S1 起把它固化，不要退化。

### 目录约定（单仓，不建 monorepo）

```
src/core/              零平台依赖，纯 node 可直接跑（Vitest）
  agent.ts             ✔ 已满足（注入 callLLM）
  types.ts             领域类型（shared/types 从这里向上扩展）
  logger-types.ts      日志接口（平台层注入实现）
  petState.ts          S1 情绪状态机
  quips.ts             S1 台词选择
  memory.ts            S2 记忆抽取 / 裁剪 / 淘汰
  notebook.ts          S2 日记拼装
  mailbox.ts           S3/S5 瓶子规则（7 天沉海 / 代号 / 同频池）
src/data/              内容资产：quips.json / 人格卡 / 日记模板 / 信纸定义
src/main/              Electron 壳：窗口 / 托盘 / IPC / 服务（平台能力注入 core）
src/preload/           contextBridge 白名单
src/renderer/          pet（命令式）/ chat · settings · consent · legal（React）
src/shared/            通道名 / zod schema / CompanionApi 契约
（手机端未来另仓库依赖发布后的 core 包，见「不做什么」）
```

### 五条硬规则

1. **core 不得** import `electron` / `node:fs` / `node:path` / `node:os` 等平台模块，
   不得使用 `window`、`document`、`process.platform`，也不得 import core 之外的模块。
   守护：`node scripts/check-core-boundary.js`（已加入 `npm run check:core`）。
2. **core 通过参数接收依赖**：`{ now, storage, net, events }`，不读全局。
3. **领域数据可 JSON 序列化**，带 `id` + `createdAt`（UTC ISO）。同步时一定会要。
4. **状态机只输出抽象动作** `{ mood, action, intensity }`，不输出动画。
   桌面渲染成 SVG 动画；手机渲染成通知、小组件、锁屏文案。
5. **内容资产放 `src/data/`**，不内嵌在 HTML / 组件里。手机端直接复用。

### 三个手机端反向约束（今天就要考虑）

| 约束 | 影响今天的什么 |
|---|---|
| **无常驻进程** | 桌面靠「一直醒着」做在场感；手机不行。情绪状态与表现必须分离（规则 4），并接受「手机的在场感 = 通知 + 小组件」 |
| **数据要跨设备** | 同步 → 需要身份 → 与「不做云账号」冲突。<br>**解法：匿名恢复码**——用户自持一串码，用于端到端加密的全量数据包迁移。从 S2 起就提供「导出 / 导入全量数据」，正好复用笔记本的导出能力 |
| **Key 不能进客户端** | 手机内置 Key 必被扒。`main/services/ai.ts` 的 `callLLM` 是唯一对接口，将来切到自有代理端点，客户端不持有上游 Key |

### 定价的跨端后果

iOS 数字商品只能走 IAP（约 30% 分成，且按套餐档位）：「单张 1 元」在商店端不成立。
→ **定价单位统一是「包」，不是「张」**。1 元单张只作为桌面直付的补充，不作为主线。
这也是第七节定价表把「信纸包」设为主线档位的原因。

### 不做什么

- **不提前引入跨端 UI 框架**（React Native / Flutter / Tauri）。桌面端 Electron 不重写；
  手机端要的是共享 core，不是共享 UI。
- **不现在拆 npm 包**。`src/core/` 目录约定足够，等手机端真的立项，再把 core 发布为独立包
  供手机仓库依赖——这样也不违反「不建 monorepo」。
- **不为手机端提前做同步**。先把「导出 / 导入全量数据」做好，同步是它的自然延伸。

## 七、商业化与信封设计

### 原则

> **卖信纸，不卖被听见。** 连接永远免费；付费只买包装、时机、字数。

> **信封费不是「收入机制附带信任」，而是「信任机制附带收入」。**

有成本，人才会认真写；没成本，就是刷屏。但如果允许「付费 = 更容易被捡到」，
产品就从「孤独的确认」变成「有钱人才有资格孤独」。

### 卖什么 / 绝不卖什么

| 可以卖 | 绝不卖 |
|---|---|
| 信纸样式、火漆印、邮票图案 | 被捡到的概率 / 曝光量 |
| 定时投递（只在 23:00 寄出，进深夜同频池） | 找回已沉海的瓶子 |
| 更长字数（60 → 200 字） | 对方的任何身份线索 |
| 一次性的「纪念信封」皮肤包 | 回复优先级、置顶、限时加急 |
| | 无限量发送包 |

**付费瓶子和免费瓶子，7 天沉海规则完全相同**——这是产品原则，不写进定价表。

### 定价

| 档位 | 内容 | 价格 | 约束 |
|---|---|---|---|
| 免费 | 1 封/天，猫画的信封，60 字 | 0 | 保证每个人都能被听见 |
| 单张邮票 | 装饰信封 + 200 字 | 1 元 | 每天最多 5 封付费；**仅桌面直付** |
| 信纸包 | 5 张邮票 + 5 种信纸 | 6 元 | 一次性；**跨端主档位** |
| 月卡 | 30 张邮票，**每天仍限 3 封** | 12 元 | 不做无限量 |

刻意不做：**充值余额**（只卖张数）、**付费无上限**（防花钱刷存在感）、
**订阅自动续费**（陪伴类产品高投诉项）。

### 单元经济（示意，判断结构而非预测）

假设 DAU 1 万、扔瓶率 30%：

| 项 | 计算 | 月收入 |
|---|---|---|
| 信封 | 3000 × 5% 付费 × 1 元 × 30 天 | ≈ 4,500 元 |
| 信纸包 | 300 人 × 6 元 | ≈ 1,800 元 |
| 服务器 | Workers + KV 免额内 | ≈ 0 |

**信封收费撑不起生意，但能覆盖成本并自然筛掉垃圾内容**，还降低审核成本。

真正的主线收入（MAU 3 万示意）：

| 收入结构 | 客单价 | 转化 | 收入 |
|---|---|---|---|
| **角色包 / 皮肤**（主） | 12–18 元 | 3% | ≈ 1.4 万 |
| **年度笔记本**（日记 + 瓶子的电子版 / 实体书） | 39 / 69 元 | 1% | ≈ 1.2 万 |
| 信纸 / 信封（辅，象征性） | 6–12 元 | 5% | ≈ 0.5 万 |

年度笔记本是最看好的变现出口：一次性、高毛利、强情感，把留存 / 日记 / 许愿瓶收束成
一个可交付物，而且**不卖连接**。

### 渠道现实（必须先解决）

**Windows 桌面没有应用商店结算通道。** 微信 / 支付宝经营性收款需要企业或个体工商户资质；
个人收款码做经营性收费合规性存疑。在定价之前先确认收款主体：

- 个人版：赞赏码过渡（非经营性）
- 正式版：个体工商户 / 企业资质 + 合规支付通道

| 阶段 | 做什么 | 门槛 |
|---|---|---|
| S5–S6 | 全免费，观察数据 | — |

## 十、风险

| 风险 | 应对 |
|---|---|
| 打扰过度导致卸载 / 关自启 | 打扰预算 + 话少模式 + 反向指标监控 |
| 联网社交没人扔 | 先做 S3 验证；S5 先只读；官方内容池 + 猫兜底 |
| 内容审核成本与监管 | 公开版不做社交；无图片；正则拦截；举报下架 |
| 隐私承诺被打破 | opt-in 默认关；匿名令牌；协议版本递增；不绑身份 |
| 付费 + UGC 合规等级上升 | 个人版 / 邀请制先行；18+ 自我声明；支付即成年；协议随定价更新 |
| 「付费才能被听见」舆论 | 产品里不出现「付费 → 被捡到」的文案链；付费规则公开 |
| 收款资质缺失 | S6 前置阻塞项；先赞赏码过渡，再办个体工商户 |
| 后端可用性拖累角色体验 | AI 与社交全部失败静默降级，角色永远可用 |
| LLM 成本失控（内置 Key 版） | 微交互本地化；日记模板优先，只在有素材时调模型 |
| 美术 / 动画产能 | 情绪优先于动作数量；先做能复用同一张 SVG 的表情与位移 |
| **平台绑定（手机端返工）** | core 零平台依赖 + 边界检查脚本；状态机不输出动画；数据可导出 / 导入 |
| 手机端与桌面端体验割裂 | 先做恢复码而不是云账号；视觉语言同一套 tokens |
