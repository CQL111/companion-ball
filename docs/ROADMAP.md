## 一、定位

**它不是你的助手，是住你桌面上的一个小家伙。**

陪伴型角色的价值不在功能清单，而在于「你没看着它的时候它也活着」。
工具型桌面 AI 拼不过通用助手；养成型桌宠拼不过内容产能。我们能赢的地方是**性格、记忆、细节**。

### 一句话

> **我们不是做桌宠的，我们做的是会陪你的手账。**
> 桌宠是获客，笔记本是留存，年度本是变现。

### 四根支柱 + 一个容器

1. **在场感** —— 不点它，它也在动：呼吸、眨眼、打盹、伸懒腰、睡觉。
2. **记忆** —— 它记得你说过的话。这是「宠物」和「玩具」的分水岭。
3. **仪式** —— 每天有一个理由见它。不是每日运势（那是 fortune-ball 的领域）。
4. **期待**（S3 后新增）—— 它记得**还没发生的事**：面试、考试、纪念日。
   没有「未来的事」，用户就没有理由明天再来。
5. **猫的笔记本**（一等公民，不是「日记功能」）—— 同时是**记忆的界面**、
   **仪式的入口**、**许愿瓶的归宿**、**期待的落点**。详见第五节。

没有笔记本，记忆只活在聊天上下文里，用户永远不知道它记住了什么——
记忆功能等于没做。台词库决定它**会不会**说话，笔记本决定它**是什么人**。

### 北极星：语言资产

「它记得你」不是一个功能，是一个**资产账户**：听见 → 记住 → 接住。
动作、皮肤、台词库对手一周可抄；用户半年攒下的日记、记忆、瓶子、页边一句话抄不走。
**每加一个功能，先问：它让这份语料更厚了吗？更可导出吗？**

### 刻意不做（非目标）

| 不做 | 原因 |
|---|---|
| 助手功能（天气查询、写代码、日程管理） | 通用桌面对话产品已经赢下这个市场，进入即无护城河 |
| 运势 / 黄历 / 签文 / 抽卡 | 与陪伴定位冲突，且属于 fortune-ball（见 `CLAUDE.md` 硬约束） |
| 传统交友（匹配 → 加好友 → 私聊） | 陌生人私聊必然引入骚扰与诈骗；产品矛盾见第四节 |
| 云账号 / 社交主页 / 关注链 | 陪伴是私密的；账号是一切社交压力的起点 |
| 把用户数据上传做「全局数据飞轮」 | 你唯一能打的牌是隐私；不做模型训练，上传改进不了任何东西 |
| 读取窗口标题 | 隐私红线。感知只用 `powerMonitor` 的空闲 / 锁屏状态 |
| **状态值 / 好感度 / 金币经济** | 一上屏就变养成游戏，与「说感受不说数据」「一个数字都不显示」冲突（Mochi 的反面，见 PRODUCT-THESIS 第二节） |
| **待办 / 日历 / 闹钟式提醒** | 会变成 Todoist 换皮。我们做的是「记得这件事的猫」，不是提醒工具 |
| **健康判断（吃了没 / 睡得好不好）** | 滑向健康监测，有合规风险；只取「事件」，不取「判断」 |

### 两条设计红线

- **打扰预算**：默认安静；主动开口每天 ≤2 次且深夜不主动；气泡不抢焦点、3 秒自灭；
  设置里提供「话多 / 话少」调节。桌宠第一大流失原因是烦，不是少。
  **越重要的事越不能说两遍**——事件记忆不享有预算特权。
- **微交互不走 LLM**：点击必须在 100ms 内有反应，走本地状态机 + 台词库。
  AI 只负责浮窗里的深聊与「有素材时」的记忆抽取。

>

> 网页端漂流瓶**只读橱窗**；新闻**官方编辑人工发布**；后台**API Key + TOTP**（不用 Workers Paid）；

**即使是私人闭环，也要逐级验证**：P1 不达标就不做 P1.5/P2（见第七节闸门）。

**手机端不在本表**——它是一次独立的产品决策（渠道、审核、支付、推送都不同），
但**每一阶段都要为它预留**：分层与跨端规则见第六节。**平台架构（网页 / 后台 / monorepo 结构 /
新闻管道 / 资源评估）见 [`PLATFORM.md`](PLATFORM.md)。**

## 三、分阶段说明

> 排列顺序：**进行中与未开始的阶段在前，已完成阶段在后（存档）**。版本号顺序见第二节总表。

### P0.5 · 不说话的身体（0.9.4）✅ 已完成

> P0 已经让「每句话都有原因」。这一版不加一句话，只让**需求可以被看见**——
> 用户把画面上的一举一动当真之前，得先看到它「想要什么」，而不是先听到。

- 新增 `core/needMotion.ts`：需求 → 动作计划（纯函数，零平台依赖）
  - **饿了** → 走到最近的屏幕边缘，贴着边待着
  - **无聊** → 走开一段再停下（不是乱跑，是「没事做」）
  - **想你** → 走到鼠标附近停下；**没有鼠标位置就不动**（宁可不说也不瞎走）
- 复用现有 14 动作 × 两视角契约，**不新增渲染路径**
- 一次身体表达最多 12 秒；睡觉 / 打盹 / 菜单打开 / 拖动中一律不表达
- **身体先于语言**：需求先有动作，台词仍由 `core/speech.ts` 统一决定
- **顺带修复**：`stepLoco` 的 `walk` 分支原本不检查 `canWander`，
  导致「睡着了还在走」「打开菜单它还在走」的穿帮（0.9.0 起就存在）
- **验收**：252 单测；新增真机验证 `tests/e2e/needmotion.mjs` 6/6
  （16 次采样 9 次位移 / 15 次动作；睡眠态位置不变）

### P1 · 你不在的时候（0.9.5，M1 缺席日志）✅ 已完成

> 所有 AI 陪伴产品都在优化「你在的时候」（聊天）；只有桌面端能优化「你不在的时候」。

- 新增 `core/absence.ts`：素材 = **缺席时长 × 回来时段 × 天气 × 季节**，纯本地零 token
- 三条硬规则，每条都有测试锁死：
  - **确定性**：FNV 哈希做种子，同一段缺席永远同一句（否则每次打开笔记本都变）
  - **允许空白**：少于 8 小时不写
  - **不说数字**：不写「你离开 9 小时」，写「你走了很久」
- 不制造愧疚：测试禁掉「你怎么才回来」这类句子
- 天气优先、季节兜底——**同一场雨原则**
- `presenceWatcher` 记录离开起点，回来时写进当天日记
- **修复**：`ensureDailyDiary` 会重算覆盖整天，把缺席内容冲掉。
  `DiaryEntry` 新增 `source: 'template' | 'absence'`，模板日记遇到缺席日记时接在后面而不是替换
- **验收**：270 单测；新增真机验证 `tests/e2e/absence.mjs` 9/9
  （9h 生成、2h 不写、10 天内容不同、不被覆盖、≤4 句）

### P1.5 · 它记得那一天（0.9.6，M2 事件记忆）✅ 已完成

> 记忆不只记过去，还要预支未来。用户随口说「我下周三要面试」，她期待的不是闹钟，是**它记得**。
> 完整规格见 [`OCCASIONS.md`](OCCASIONS.md)。

- **听懂**：`core/occasions.ts` 事件词 + 日期词正则，**零 token**
  -「下周三 / 明天 / 12月3日 / 月底 / 这周末」，跨月跨年正确
  - 口语识别「面字节」；否定句不抽（「我上周面试完了」）
- **记住**：存「事件 + 日期（只到日）+ 原话」，上限 10 条，超出淘汰最远的；
  同一天同类不重复；状态机 `upcoming → passed | dismissed`
- **接住**：T-1 提一句 → 当天**身体动作**而不是气泡 → T+1 问一句结果；每条各只触发一次
- **隐式确认**：不弹窗；抽到就写进当天日记「今天听你说…我会记得的。」，用户可划掉
- **开关**：「让它记住还没发生的事」默认开；关闭即清空并在日记留一句说明
- **不做**：日历视图、待办列表、准时闹钟、「还剩 N 天」这类数字
- **验收**：299 单测（occasions 29）；真机 `tests/e2e/occasions.mjs` 14/14；
  月触发 ≥3；事件删除率 <20%；
  **记错后纠正能被修正并记住**——这条比「记得准」更重要，因为前者像人，后者像工具。

### M7 · 日常记事（0.9.9）✅ 已完成

> 用户提出：「我说今天花了10块，它应该以什么形式提醒我？」
>
> 判断：这不只是记账——**记账 / 写日记 / 列待办都失败在同一个地方：
> 报备需要听众，但账本是死的**。你只要说一句，不用打开第二个 App。

- `core/dailyLog.ts`：动词 + 数字 + 量词（花了10块 / 喝了3杯 / 跑了5公里），零 token
- **晚间复述**：18 点后第一次评估时复述一次，最多两条
  *「今天你说花了10块。还说你喝了3杯咖啡。」*
- **一天只一次，错过不补**——猫不该像个有未读消息的应用
- 设计红线（都写成测试）：
  - **不维护总额**：没有「今日合计」，不出现「一共/合计/累计」
  - **不评价**：不说「花得有点多」
  - **不追问**：不出现「还有别的花销吗」
  - **数字归属**：用户的数字可以复述；关系的数字（陪你 3 小时）永远不出现
- **验收**：323 单测（dailyLog 24）；真机 `tests/e2e/dailylog.mjs` 12/12

### S4 修补 · 回来时认出你（0.9.9）✅ 已完成

> 用户：「电脑已经息屏了，重新打开、输完密码之后，应该可以跟我有一个互动。」
>
> 根因不是一处：**离开/回来有四条路径各写各的**，叠起来让它看不见你回来——
> 没有 suspend/resume；离开时长用睡眠后归零的空闲秒数算；渲染端从不传
> `justReturned`；`dispatch` 又绕过门槛直接念台词。

- `core/presence.ts` 统一为纯函数转移 `sampleAbsence` / `suspendAbsence` / `resumeAbsence`，
  轮询 / 锁屏 / 挂起 / 唤醒四个入口走同一组规则，主进程只有一个状态 owner
- **离开起点 = 挂起时刻，离开时长 = 唤醒时刻反推**（不信任睡眠后的空闲秒数）——这条是 S4 的正确性核心
- `returned` 长离开时把 `lastInteractAt` 拨到「刚才」，否则下一秒 tick 会判 `sleep`，`sulk` 撑不到一秒
- **回来是惊喜不是闹钟**：`RETURN_GREET_MIN_MS = 30 分钟`，低于它只做身体反应不开口
- **验收**：338 单测（petState 5 / presence 8 / speech 2）；真机 `tests/e2e/return.mjs` 5/5

### P2 · 页边一句话（M4 笔记本合写）✅ 已实现（未发版）

> 让笔记本从猫的独白变成两个人的合写。

- 日记每页可留**一行**私密回话；不进聊天、无即时回复
- 猫可能在下一次日记里提一句，也可能不提（**允许不回**：呼应许愿瓶的「无回声」伦理）
- 页边一句话是最好的记忆素材；它也是 S7 年度本里「只属于两个人」的部分
- **硬限制**：1 行、非即时、不可公开——防止它变回聊天

**已实现**：
- `core/notebook.ts`：`DiaryEntry.margin`，与 `lines` 完全隔离。
  `upsertDiary` 原样保留 margin——猫每天重算日记不会冲掉用户的话（3 条测试守着）。
  空白页也能留话（「空白不落盘」不能吞掉用户写的东西）。

## 四、猫邮局：为什么不是「交友」

传统交友的本质是**建立关系**：匹配 → 加好友 → 私聊 → 维护。
这条路对桌宠是毒药——私聊一旦存在，骚扰、诈骗、导流全部进来。

我们要的是**孤独的确认，不是关系的建立**：一次性的、无回声的、不可追问的连接。
用户是「孤独但不想社交」的人，他们要的是「世界上还有别人也这样」，不是新朋友。

| | 传统漂流瓶 | 交友 App | 猫邮局 |
|---|---|---|---|
| 连接 | 捡到 → 加好友 | 匹配 → 私聊 | 捡到 → 看一眼 → 回一句 → **断** |
| 身份 | 头像昵称 | 全套人设 | 每次随机代号，不复用 |
| 关系 | 可延续 | 必须延续 | **结构上无法延续** |
| 频率 | 无限 | 无限 | 有配额 |
| 数字 | 已读 / 点赞 | 全套 | **一个都不显示** |

几个决定体验的细节：

- **不做固定匹配，只漂同频**：深夜扔的瓶子只漂给另一个深夜醒着的人。
- **没有数字**：没有已读、被捡次数、点赞。没有数字就没有社交比较。
- **回信不保证送达**：瓶子 7 天没人捡就沉海；你的回信对方可能早已漂走。
  错过的感觉很真实，而且天然阻断对话。
- **载体是角色不是功能**：不是「你去捡瓶子」，是「猫会出门，叼东西回来」。
  随机出门，不由用户按按钮触发。

## 五、猫的笔记本：产品的一等公民

不是「日记功能」，而是**一个容器**：

| 角色 | 说明 |
|---|---|
| 记忆的界面 | 长期记忆不能只活在 prompt 里；日记是它唯一可见的产物 |
| 仪式的入口 | 「打开猫的笔记本」比「和 AI 聊天」自然，没有聊天焦虑（不用你说话） |
| 瓶子的归宿 | S3 捡到的纸条、S5 的真瓶子，都夹进同一本 |
| 期待的落点 | P1.5 的「下周三要面试」、P2 的页边一句话，都写在这本上 |
| 语料的容器 | 年度本（S7）直接从这里编排——这是**语言资产**最厚的形态 |
| 人格的载体 | 台词是骨架，日记是血肉；这是唯一能持续积累的性格资产 |

### 写作规则

- **猫的第一人称**，2–4 句，有日期，**允许空白**——真日记不会天天有话说
- **不出现任何数字和统计**

  > ❌「今日陪伴你 3 小时 20 分钟，共对话 12 轮。」
  >
  > ✅「你今天没怎么说话。我趴在窗口看了会儿雨，等你叫我。」

- 对所有素材（含缺席、事件、页边一句话）都过猫的眼睛：**说感受，不说数据**
- 每天最多一条，有素材才写，宁可跳

### 边界

- **不同步、不分享**——那会直接推翻第四节「无回声」的设计
- **一键导出 Markdown / 全量 JSON**：用户会心疼丢，导出是最便宜的信任建设
- 页边一句话**不可公开、不可导出到他处**（导出仅在年度本与全量备份里）
- 关闭日记 = 关闭记忆的可视化，但记忆抽取本身可独立开关

## 六、分层与跨端预留（手机端）

### 结论先行

手机端不是「第二个壳」，它是一次独立的产品决策；但**领域逻辑与数据必须是同一份**。
所以从 S1 开始只守一件事：**core 层零平台依赖**。这一条今天做，成本几乎为零；
等手机端开工再补，就是重写。

### 现状：已经做对了一半

`src/core/agent.ts` 不依赖 Electron，`callLLM` 由调用方注入，Vitest 能在纯 node 下跑——
这就是正确的缝。S1 起把它固化，不要退化。

### 目录约定（单仓 monorepo）

> 2026-11-25 起：桌面端留在根目录，平台包放 `packages/`（见 [`PLATFORM.md`](PLATFORM.md) 第九节）。
> 「不建 monorepo」的原意是不与 fortune-ball 共享代码包，平台 monorepo 不违反这一点。

```
companion-ball/           私有仓库
  src/core/               桌面端领域层（零平台依赖）
  packages/contracts/     两端共享的常量 / 类型 / 校验 / 错误码
  packages/server/        Workers + D1 migrations
  packages/web/           Astro 橱窗 + 新闻
  packages/admin/         Vite + React 19 后台
```

```
src/core/              零平台依赖，纯 node 可直接跑（Vitest）
  agent.ts             ✔ 已满足（注入 callLLM）
  types.ts             领域类型（shared/types 从这里向上扩展）
  logger-types.ts      日志接口（平台层注入实现）
  petState.ts          S1 情绪状态机
  quips.ts             S1 台词选择
  memory.ts            S2 记忆抽取 / 裁剪 / 淘汰
  notebook.ts          S2 日记拼装
  mailbox.ts           S3/S5 瓶子规则（7 天沉海 / 代号 / 同频池）
  absence.ts           P1 缺席日志（时长 × 时段 × 天气 → 日记素材）
  occasions.ts         P1.5 事件记忆（未来的事 → 记住 → 接住）
src/data/              内容资产：quips.json / 人格卡 / 日记模板 / 缺席素材 / 信纸定义
src/main/              Electron 壳：窗口 / 托盘 / IPC / 服务（平台能力注入 core）
src/preload/           contextBridge 白名单
src/renderer/          pet（命令式）/ chat · settings · consent · legal（React）
src/shared/            通道名 / zod schema / CompanionApi 契约
（手机端未来另仓库依赖发布后的 core 包，见「不做什么」）
```

### 五条硬规则

1. **core 不得** import `electron` / `node:fs` / `node:path` / `node:os` 等平台模块，
   不得使用 `window`、`document`、`process.platform`，也不得 import core 之外的模块。
   守护：`node scripts/check-core-boundary.js`（已加入 `npm run check:core`）。
2. **core 通过参数接收依赖**：`{ now, storage, net, events }`，不读全局。
3. **领域数据可 JSON 序列化**，带 `id` + `createdAt`（UTC ISO）。同步时一定会要。
4. **状态机只输出抽象动作** `{ mood, action, intensity }`，不输出动画。
   桌面渲染成 SVG 动画；手机渲染成通知、小组件、锁屏文案。
5. **内容资产放 `src/data/`**，不内嵌在 HTML / 组件里。手机端直接复用。

### 三个手机端反向约束（今天就要考虑）

| 约束 | 影响今天的什么 |
|---|---|
| **无常驻进程** | 桌面靠「一直醒着」做在场感；手机不行。情绪状态与表现必须分离（规则 4），并接受「手机的在场感 = 通知 + 小组件」 |
| **数据要跨设备** | 同步 → 需要身份 → 与「不做云账号」冲突。<br>**解法：匿名恢复码**——用户自持一串码，用于端到端加密的全量数据包迁移。从 S2 起就提供「导出 / 导入全量数据」，正好复用笔记本的导出能力 |
| **Key 不能进客户端** | 手机内置 Key 必被扒。`main/services/ai.ts` 的 `callLLM` 是唯一对接口，将来切到自有代理端点，客户端不持有上游 Key |

### 定价的跨端后果

iOS 数字商品只能走 IAP（约 30% 分成，且按套餐档位）：「单张 1 元」在商店端不成立。
→ **定价单位统一是「包」，不是「张」**。1 元单张只作为桌面直付的补充，不作为主线。
这也是第七节定价表把「信纸包」设为主线档位的原因。

### 不做什么

- **不提前引入跨端 UI 框架**（React Native / Flutter / Tauri）。桌面端 Electron 不重写；
  手机端要的是共享 core，不是共享 UI。
- **不现在为手机端拆 npm 包**。`src/core/` 目录约定足够；手机端立项时再决定复用方式。
- **不为手机端提前做同步**。先把「导出 / 导入全量数据」做好，同步是它的自然延伸。

## 七、闸门、商业化与信封设计

### 闸门：每个阶段都是在验证一个假设

不加新功能之前，先承认一个事实：我们不缺功能，缺**证据**。每个节点都不满足就停：

| 节点 | 在验证什么 | 继续的条件 | 不满足就 |
|---|---|---|---|
| S3 部署后 4 周 | 陌生人之间愿不愿意互投 | 回信率 ≥10%；有效瓶子不断供 | 停 S5/S6，回到「猫邮局没开门」+ 猫兜底 |
| P1 后 2 周 | 用户不在的时候，会不会回来看 | 缺席后本次会话打开笔记本 ≥60% | 停 P1.5/P2，先回答「用户为什么每天打开它」 |
| P1.5 后 4 周 | 未来的事能不能变成回来的理由 | 月触发 ≥3；事件删除率 <20% | 只保留起名日 / 首瓶日，砍推断事件 |
| P2 后 4 周 | 用户愿不愿意落笔 | 打开者周留一句 ≥30% | S7 降级为纯猫的日记本 |
| S7 首季 | 年度本是不是真正的变现出口 | 实体转化 ≥1%（观测） | 只做数字版 |

### 原则

> **卖信纸，不卖被听见。** 连接永远免费；付费只买包装、时机、字数。

> **信封费不是「收入机制附带信任」，而是「信任机制附带收入」。**

有成本，人才会认真写；没成本，就是刷屏。但如果允许「付费 = 更容易被捡到」，
产品就从「孤独的确认」变成「有钱人才有资格孤独」。

### 卖什么 / 绝不卖什么

| 可以卖 | 绝不卖 |
|---|---|
| 信纸样式、火漆印、邮票图案 | 被捡到的概率 / 曝光量 |
| 定时投递（只在 23:00 寄出，进深夜同频池） | 找回已沉海的瓶子 |
| 更长字数（60 → 200 字） | 对方的任何身份线索 |
| 一次性的「纪念信封」皮肤包 | 回复优先级、置顶、限时加急 |
| **年度笔记本（实体）** | 无限量发送包 |

**付费瓶子和免费瓶子，7 天沉海规则完全相同**——这是产品原则，不写进定价表。

### 定价

| 档位 | 内容 | 价格 | 约束 |
|---|---|---|---|
| 免费 | 1 封/天，猫画的信封，60 字 | 0 | 保证每个人都能被听见 |
| 单张邮票 | 装饰信封 + 200 字 | 1 元 | 每天最多 5 封付费；**仅桌面直付** |
| 信纸包 | 5 张邮票 + 5 种信纸 | 6 元 | 一次性；**跨端主档位** |
| 月卡 | 30 张邮票，**每天仍限 3 封** | 12 元 | 不做无限量 |
| 年度笔记本 | 全年日记 + 瓶子 + 页边，实体 | 39 / 69 元 | 数字版免费；按需印刷；一次性 |

刻意不做：**充值余额**（只卖张数）、**付费无上限**（防花钱刷存在感）、
**订阅自动续费**（陪伴类产品高投诉项）。

### 单元经济（示意，判断结构而非预测）

假设 DAU 1 万、扔瓶率 30%：

| 项 | 计算 | 月收入 |
|---|---|---|
| 信封 | 3000 × 5% 付费 × 1 元 × 30 天 | ≈ 4,500 元 |
| 信纸包 | 300 人 × 6 元 | ≈ 1,800 元 |
| 服务器 | Workers + KV 免额内 | ≈ 0 |

**信封收费撑不起生意，但能覆盖成本并自然筛掉垃圾内容**，还降低审核成本。

真正的主线收入（MAU 3 万示意）：

| 收入结构 | 客单价 | 转化 | 收入 |
|---|---|---|---|
| **年度笔记本**（主，M5） | 39 / 69 元 | 1% | ≈ 1.2 万 |
| **角色包 / 皮肤** | 12–18 元 | 3% | ≈ 1.4 万 |
| 信纸 / 信封（辅，象征性） | 6–12 元 | 5% | ≈ 0.5 万 |

年度笔记本是最看好的变现出口：一次性、高毛利、强情感，把留存 / 日记 / 许愿瓶 / 页边一句话
收束成一个可交付物，而且**不卖连接**。

### 渠道现实（必须先解决）

**Windows 桌面没有应用商店结算通道。** 微信 / 支付宝经营性收款需要企业或个体工商户资质；
个人收款码做经营性收费合规性存疑。在定价之前先确认收款主体：

- 个人版：赞赏码过渡（非经营性）
- 正式版：个体工商户 / 企业资质 + 合规支付通道
- 年度本实体：按需印刷平台（如 POD）的合规主体

### 上线顺序

| 阶段 | 做什么 | 门槛 |
|---|---|---|
| S3–S6 | 全免费，观察数据 | 闸门表（本节上方）逐项通过 |

## 九、已决事项

1. **第四根支柱「期待」成立**：私人闭环（P1 → P1.5 → P2）先于社交公开化（S5 → S6）。
2. **北极星是语言资产厚度**：「听见 → 记住 → 接住」；不是互动次数。
3. **事件记忆不做成日历 / 待办**：它写进日记、用身体表达、允许记错；详见 `OCCASIONS.md`。
4. **猫的笔记本立为一等公民**，统一收纳日记、记忆、瓶子、事件、页边。
5. **社交连接免费**，付费只卖信纸 / 信封 / 装饰与投递方式；**年度本是最看好的变现出口**。
6. **为手机端预留**：领域逻辑（状态机 / 记忆 / 笔记本 / 瓶子 / 缺席 / 事件）放 `src/core/`，
   零平台依赖；平台能力走适配器。不提前引入跨端 UI 框架，不提前拆包。
7. **Mochi 只作镜鉴**：学「一句话改变世界」的方向，不学数值、惩罚、经济与论坛。

## 十、风险

| 风险 | 应对 |
|---|---|
| 打扰过度导致卸载 / 关自启 | 打扰预算 + 话少模式 + 反向指标监控；**重要事件也不享预算特权** |
| 事件记忆记错 / 越权感 | 只到「日」、隐式确认、可划掉、推断可关；纠错本身是互动 |
| 缺席日志被当成「监控」 | 只用已有空闲 / 天气 / 时间素材，不新增感知；纯本地生成 |
| 私人闭环也许没人用 | 闸门表：P1 不达标就停 P1.5/P2，回到「用户为什么回来」 |
| 联网社交没人扔 | 先做 S3 验证 + 邀请制冷启动；S5 先只读；官方内容池 + 猫兜底 |
| 内容审核成本与监管 | 公开版不做社交；无图片；正则拦截；举报下架 |
| 隐私承诺被打破 | opt-in 默认关；匿名令牌；协议版本递增；不绑身份 |
| 付费 + UGC 合规等级上升 | 个人版 / 邀请制先行；18+ 自我声明；支付即成年；协议随定价更新 |
| 「付费才能被听见」舆论 | 产品里不出现「付费 → 被捡到」的文案链；付费规则公开 |
| 收款资质缺失 | S6 前置阻塞项；先赞赏码过渡，再办个体工商户 |
| 年度本实体履约 | 按需印刷平台做履约，不做自建仓；数字版免费兜底 |
| 后端可用性拖累角色体验 | AI 与社交全部失败静默降级，角色永远可用 |
| LLM 成本失控（内置 Key 版） | 微交互本地化；事件抽取默认零 token；日记模板优先 |
| 美术 / 动画产能 | 情绪优先于动作数量；P0.5 复用现有动作契约，不新增渲染路径 |
| **平台绑定（手机端返工）** | core 零平台依赖 + 边界检查脚本；状态机不输出动画；数据可导出 / 导入 |
| 手机端与桌面端体验割裂 | 先做恢复码而不是云账号；视觉语言同一套 tokens |
